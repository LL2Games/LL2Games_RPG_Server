# LL2Games RPG 클라이언트 기획서

작성일: 2026-07-09  
기준 코드: `SERVER` 현재 구현 스펙

## 1. 목표

이 문서는 현재 서버가 지원하는 기능을 기준으로, 어떤 게임 클라이언트를 만들면 좋은지 정리한 1차 기획서다.

서버는 이미 로그인, 캐릭터 선택, 채널 선택, 채널 인증, 맵 입장, 이동 동기화, 몬스터, 전투, 경험치, 스탯, 아이템 드롭, 인벤토리, 퀵슬롯, 교환, 채팅 구조를 가지고 있다. 따라서 1차 클라이언트는 거대한 MMORPG 전체를 한 번에 만들기보다, 서버의 강점인 실시간 2D 필드 전투와 기본 성장 루프를 먼저 완성하는 방향이 적합하다.

## 2. 제안하는 게임 콘셉트

### 제목 후보

- `Mini Field RPG`
- `FieldRun`
- `Little Hunter`
- `LL2 Field`

### 한 줄 소개

작은 필드에 입장해 몬스터를 빠르게 사냥하고, 드롭 아이템과 스탯 성장으로 캐릭터를 가볍게 키우는 2D 횡스크롤 온라인 RPG.

### 메이플스토리와 다른 방향

메이플스토리처럼 2D 횡스크롤, 몬스터 사냥, 레벨업, 스탯, 아이템 수집의 재미는 가져간다. 대신 아래 요소는 더 단순하게 만든다.

- 맵을 작게 유지하고, 화면 전환과 이동 시간을 줄인다.
- 직업과 스킬을 처음부터 많이 넣지 않는다.
- 퀘스트 중심이 아니라 짧은 사냥 세션 중심으로 만든다.
- 복잡한 장비 강화, 전직, 많은 UI 창은 1차 버전에서 제외한다.
- 전투는 자동 타겟팅이 아니라 방향 기반 수동 공격으로 만든다.

## 3. 서버에서 확인된 플레이 스펙

### 서버 구조

| 서버 | 클라이언트 관점 역할 |
| --- | --- |
| LOGIN | 계정 로그인 |
| WORLD | 캐릭터 목록 조회, 채널 선택 |
| CHANNEL | 실제 게임 플레이 |
| CHAT | 채팅 |
| MAIN | 서버 데몬 관리, 클라이언트 직접 연결 대상 아님 |

### 기본 접속 흐름

1. LOGIN 서버 접속
2. `PKT_LOGIN`으로 계정 로그인
3. WORLD 서버 접속
4. `PKT_INIT_WORLD`로 계정 ID 전달
5. `PKT_SELECT_CHARACTER`로 캐릭터 목록 요청
6. `PKT_SELECT_CHANNEL`로 채널 선택
7. CHANNEL 서버 접속
8. `PKT_CHANNEL_AUTH`로 채널 인증
9. `PKT_ENTER_MAP`으로 맵 입장
10. 플레이 패킷 송수신 시작

### 현재 콘텐츠 데이터

현재 서버 데이터 기준 1차 필드는 `Henesys` 한 맵이다.

| 항목 | 현재 값 |
| --- | --- |
| 맵 ID | `100000000` |
| 맵 이름 | `Henesys` |
| 몬스터 | Green Slime, Blue Snail, Orange Mushroom |
| 리스폰 | 맵 데이터 기준 10초 |
| 아이템 | HP/MP 포션, 사과, 재료 아이템 |
| 스킬 | 기본 공격, Knight Slash, Archer Shot |

### 지원되는 주요 플레이 기능

- 플레이어 위치 이동 동기화
- 다른 플레이어 입장/스냅샷 수신
- 몬스터 스냅샷/이동/피격/리스폰 수신
- 플레이어 기본 공격/스킬 공격 송신
- 서버 권위 전투 판정
- 경험치 획득 및 레벨업
- STR/DEX/INT/LUK 스탯 투자
- 인벤토리 메타/아이템 목록 수신
- 인벤토리 슬롯 이동
- 아이템 사용
- 드롭 아이템 생성/삭제/줍기
- 퀵슬롯 목록/설정
- 플레이어 간 교환
- 채팅

## 4. 1차 클라이언트 게임 방향

### 핵심 플레이 루프

1. 로그인한다.
2. 캐릭터를 선택한다.
3. 채널에 접속해 필드에 입장한다.
4. 좌우 이동으로 몬스터 위치를 잡는다.
5. 기본 공격 또는 스킬로 몬스터를 처치한다.
6. 경험치와 드롭 아이템을 얻는다.
7. 포션을 사용하거나 퀵슬롯에 등록한다.
8. 레벨업 시 AP를 STR/DEX/INT/LUK에 투자한다.
9. 다른 유저와 같은 필드에서 사냥하거나 교환한다.

### 첫 버전의 재미 포인트

- 짧은 시간 안에 몬스터를 잡고 숫자가 오르는 즉각적인 성장감
- 단순하지만 손맛 있는 방향 기반 공격
- 아이템이 바닥에 떨어지고 직접 줍는 수집감
- 다른 플레이어가 같은 맵에서 움직이고 공격하는 온라인 느낌
- 스탯 투자로 내 캐릭터가 조금씩 달라지는 감각

## 5. 조작 기획

| 입력 | 동작 |
| --- | --- |
| A / Left | 왼쪽 이동 |
| D / Right | 오른쪽 이동 |
| Space | 점프 또는 회피, 서버에 점프 로직이 없으면 클라이언트 연출만 1차 적용 |
| Ctrl / J | 기본 공격 |
| Q / W / E / R | 퀵슬롯 스킬 또는 아이템 |
| Z | 가까운 드롭 아이템 줍기 |
| I | 인벤토리 |
| S | 스탯 창 |
| Enter | 채팅 입력 |
| Esc | 메뉴/창 닫기 |

현재 서버는 이동 패킷에 x, y, speed, dir을 받으므로 클라이언트는 물리 이동 결과를 주기적으로 서버에 보낸다. 공격은 hit 대상이 아니라 `skill_id`와 `attack_dir`만 보내고, 서버가 실제 피격 판정을 수행한다.

## 6. 화면 구성

### 로그인 화면

필수 기능:

- 계정 ID 입력
- 비밀번호 입력
- 로그인 버튼
- 실패 메시지 표시

1차에서는 회원가입 UI를 넣지 않아도 된다. 서버에는 `PKT_REGISTER` enum은 있지만 실제 LoginPacketFactory에는 로그인 핸들러만 연결되어 있으므로, 회원가입은 DB 또는 별도 툴로 처리하는 것이 안전하다.

### 캐릭터 선택 화면

필수 기능:

- 캐릭터 목록 표시
- 캐릭터 이름, 레벨, 직업 표시
- 선택 후 채널 선택 화면으로 이동

주의:

- 서버의 `PKT_SELECT_CHARACTER`는 현재 payload를 읽지 않고, 세션 account_id 기준으로 캐릭터 목록을 내려주는 구조다.
- 캐릭터 생성/삭제 UI는 서버 기능 확인 후 2차로 미룬다.

### 채널 선택 화면

필수 기능:

- 채널 목록 표시
- 채널 상태 표시: 정상, 혼잡, 만원, 비활성
- 선택 시 CHANNEL 서버 IP/PORT를 받아 접속

현재 WORLD 서버는 선택한 channel_id에 대해 `ip`, `port`, `channel_state`를 반환한다.

### 게임 화면

권장 레이아웃:

- 중앙: 2D 횡스크롤 필드
- 상단 왼쪽: 캐릭터 이름, 레벨, HP/MP
- 상단 오른쪽: 채널, 맵 이름, 접속 상태
- 하단 중앙: 퀵슬롯
- 하단 왼쪽: 채팅
- 하단 오른쪽: 인벤토리/스탯/교환 버튼

클라이언트 첫 화면은 로그인 이후 바로 게임 화면으로 들어가는 실사용형 구조가 좋다. 별도 랜딩 페이지는 만들 필요가 없다.

## 7. 전투 기획

### 전투 방식

전투는 서버 권위 방식으로 만든다.

- 클라이언트는 공격 입력, 방향, 스킬 ID만 보낸다.
- 서버가 스킬 쿨타임, MP, 사거리, 각도, 몬스터 충돌 판정을 계산한다.
- 서버가 몬스터 피격 결과를 모든 플레이어에게 브로드캐스트한다.
- 클라이언트는 결과를 받아 데미지 숫자, 피격 이펙트, 사망 연출을 보여준다.

### 기본 공격

- 기본 공격 스킬 ID는 무기 타입을 활용한다.
- 현재 기본 한손 무기 값은 `29001`이다.
- 범위는 서버 데이터 기준 80, 각도 45도, 최대 타겟 1이다.

### 액티브 스킬

| 직업 계열 | 스킬 ID | 이름 후보 | 서버 key | 성격 |
| --- | --- | --- | --- | --- |
| Knight | `20001` | Slash | `knight.slash_01` | 근접 부채꼴 공격 |
| Archer | `21001` | Shot | `Archer.Shot_01` | 현재 데이터는 투사체 카테고리지만 cast_type은 MELEE_ARC로 되어 있어 확인 필요 |
| Common | `29001` | Basic Attack | `common.basic_attack.onehand_sword` | 기본 공격 |

서버 코드의 RootJob enum과 스킬 JSON 주석 사이에 직업 코드 표기가 어긋난 부분이 있다. 클라이언트는 우선 서버가 보내는 `job` 값을 그대로 표시하고, 직업 이름 매핑은 별도 테이블로 관리한다.

## 8. 성장 기획

### 레벨업

몬스터 처치 시 서버가 경험치를 지급하고, 레벨업 여부를 내려준다.

클라이언트 표시:

- 획득 경험치 플로팅 텍스트
- 경험치 바 갱신
- 레벨업 이펙트
- AP 증가 알림

### 스탯

현재 서버는 네 가지 기본 스탯을 지원한다.

| 스탯 | 권장 클라이언트 설명 |
| --- | --- |
| STR | 근접 공격 중심 |
| DEX | 명중/원거리 공격 중심 |
| INT | 마법 확장용 |
| LUK | 회피/치명 확장용 |

1차 버전에서는 직업별 추천 스탯 버튼을 추가하는 것이 좋다.

- Knight: STR 추천
- Archer: DEX 추천
- Mage: INT 추천
- Thief: LUK 추천

단, 서버의 실제 데미지 공식 확인 전까지 추천 UI는 안내 수준으로만 둔다.

## 9. 아이템/인벤토리 기획

### 인벤토리 타입

| 타입 값 | 의미 |
| --- | --- |
| 0 | Equip |
| 1 | Consume |
| 2 | Etc |
| 3 | Setup |
| 4 | Cash |

1차 UI에서는 `Consume`, `Etc` 탭을 우선 만들고, `Equip`은 빈 탭으로 둬도 된다. 현재 데이터에 장비 아이템 JSON은 보이지 않고, 포션과 재료 아이템이 중심이다.

### 소비 아이템

| 아이템 ID | 이름 | 효과 |
| --- | --- | --- |
| `2000000` | Red Potion | HP +50 |
| `2000001` | Orange Potion | HP +150 |
| `2000003` | Blue Potion | MP +100 |
| `2010009` | Green Apple | MP +30 |

### 재료 아이템

| 아이템 ID | 이름 |
| --- | --- |
| `4000000` | Blue Snail Shell |
| `4000019` | Green Snail Shell |
| `4000001` | Mushroom Hat |
| `4010000` | 황동 구리 |

### 드롭 아이템

드롭은 서버에서 `dropId`, `itemId`, `count`, `x`, `y`로 내려온다. 클라이언트는 바닥 오브젝트로 표시하고, 플레이어가 `Z`를 누르면 가까운 드롭의 `dropId`를 `PKT_PLAYER_PICKUP_ITEM`으로 보낸다.

## 10. 멀티플레이 기획

### 다른 플레이어 표시

서버는 새 플레이어 입장과 기존 플레이어 스냅샷을 제공한다.

클라이언트는 다음을 표현한다.

- 캐릭터 위치
- 바라보는 방향
- 이동 상태
- 공격 애니메이션
- 피격/사망 상태

### 채팅

1차에서는 같은 서버에 접속한 유저 간 기본 채팅만 구현한다.

추천 UI:

- 하단 왼쪽 반투명 로그 영역
- Enter로 입력 시작
- 일반 메시지와 시스템 메시지 색상 구분

### 교환

서버는 교환 요청, 수락, 시작, 준비, 확정, 취소, 아이템 추가 패킷을 가지고 있다. 다만 1차 클라이언트에서는 필수 재미 루프가 아니므로 우선순위를 낮춘다.

권장 구현 순서:

1. 교환 요청 팝업
2. 교환 창 열기
3. 아이템 추가
4. 양쪽 준비
5. 확정/취소

## 11. 비주얼 방향

### 전체 톤

메이플스토리의 밝은 2D 느낌은 참고하되, 더 단순한 실루엣과 읽기 쉬운 UI를 목표로 한다.

권장 스타일:

- 캐릭터: 작은 픽셀 또는 저해상도 2D 스프라이트
- 몬스터: 단순한 형태, 색상으로 구분
- 배경: 레이어 2~3개 정도의 가벼운 패럴랙스
- 이펙트: 공격 방향과 피격 여부가 잘 보이는 짧은 VFX
- UI: 게임 화면을 가리지 않는 작고 명확한 패널

### 첫 맵 콘셉트

`Henesys` 이름은 남아 있지만, 클라이언트 콘셉트는 메이플 원본과 다르게 잡는다.

제안: `초록 언덕 훈련장`

- 넓은 단일 발판
- 좌우에 몬스터 스폰
- 중앙에 플레이어 시작 위치
- 배경은 마을보다 야외 훈련장 느낌
- 추후 포탈을 통해 다른 소형 필드로 확장

## 12. 네트워크 프로토콜 요약

### 공통 패킷 구조

서버 패킷 헤더:

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| length | uint16 | 헤더 포함 전체 길이 |
| type | uint16 | 패킷 타입 |

body는 문자열 필드 배열이다. 서버 `MakeBody`는 각 필드를 `uint16 length + raw string`으로 붙인다.

주의:

- `ParseLengthPrefixedString`은 1바이트 길이 + optional 0x00 skip처럼 읽는 부분이 있어, 서버 내부 송신 포맷과 클라이언트 송신 포맷을 실제 테스트로 맞춰야 한다.
- 기존 Python 테스트 클라이언트를 참고해 클라이언트 패킷 빌더를 먼저 검증해야 한다.

### 주요 패킷

| 패킷 | 값 | 방향 | 용도 |
| --- | --- | --- | --- |
| `PKT_LOGIN` | `0x0001` | C/S | 로그인 |
| `PKT_INIT_WORLD` | `0x0005` | C/S | 월드 세션 초기화 |
| `PKT_SELECT_CHARACTER` | `0x0006` | C/S | 캐릭터 목록 |
| `PKT_SELECT_CHANNEL` | `0x0007` | C/S | 채널 선택 |
| `PKT_CHANNEL_AUTH` | `0x0009` | C/S | 채널 인증 |
| `PKT_ENTER_MAP` | `0x000A` | C/S | 맵 입장 |
| `PKT_PLAYER_MOVE` | `0x0020` | C/S | 플레이어 이동 |

## 13. 클라이언트 구현 우선순위

### Milestone 1: 네트워크 접속 검증

- 캐릭터 목록 수신
- 채널 선택 후 CHANNEL 접속

### Milestone 2: 필드 입장과 렌더링

- 몬스터 스냅샷 표시
- 몬스터 이동 패킷 반영
- 카메라 추적
- 기본 HUD 표시

- 기본 공격 송신
- 스킬 공격 송신
- 몬스터 피격/사망 연출
- 경험치/레벨업 UI 반영

- 교환 창

## 14. 서버 쪽 확인 필요 사항

클라이언트 구현 전에 아래는 한 번 정리하는 것이 좋다.

1. `PKT_CHANNEL_AUTH`의 정확한 payload 형식
2. `PKT_SELECT_CHARACTER` 응답의 캐릭터 목록 필드 순서
3. `PKT_CHANNEL_AUTH` 성공 후 서버가 자동으로 보내는 초기 패킷 목록
4. 직업 코드 매핑: `RootJob` enum과 스킬 JSON 주석의 Knight/Mage/Archer 코드 불일치
5. `Archer.Shot_01`의 `category`와 `cast_type` 불일치
6. `PacketParser::MakeBody`는 uint16 길이를 쓰는데 `ParseLengthPrefixedString`은 uint8 길이처럼 읽는 부분
7. `SendPlayerSkillList`에서 스킬 수로 `sizeof(playerSkillList)`를 보내는 부분
8. `ItemPacketSender::SendSpawnItem`에서 플레이어 루프 안에서 payload가 누적되는 부분
9. 회원가입/캐릭터 생성/삭제 기능의 실제 지원 여부

## 15. 최종 제안

이 서버에 가장 잘 맞는 1차 클라이언트는 “작은 필드 기반 2D 온라인 사냥 RPG”다.

처음부터 거대한 월드와 많은 직업을 만들기보다, 한 맵에서 아래 경험을 완성하는 것이 좋다.

- 접속이 된다.
- 내 캐릭터가 움직인다.
- 다른 유저가 보인다.
- 몬스터가 움직인다.
- 공격하면 서버 판정으로 몬스터가 맞는다.
- 몬스터가 죽고 아이템이 떨어진다.
- 아이템을 줍고 포션을 쓴다.
- 레벨업하고 스탯을 찍는다.

이 루프가 완성되면 이후 맵, 몬스터, 스킬, 장비, 파티, 퀘스트를 붙이면 된다.
